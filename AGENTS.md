# Правила для ИИ-исполнителей

Документация и отчёты — по-русски. Начать с README, docs/STATUS.md, docs/HANDOFF.md, docs/COLLABORATION.md и своего issue.

- Один issue, отдельная ветка и worktree, один writer. Писать только в разрешённых issue путях. Не запускать соседние задачи.
- Общие контракты в contracts/ и интеграционные документы принадлежат интегратору. Нужен новый контракт — предложение в issue, не несогласованная правка.
- Ни один worker не запускает/останавливает сервисы на VPS, не меняет БД, секреты или firewall и не трогает `/root/ragnarok/run`, logs и внешние worktrees.
- Не запускать Claude без явного разрешения владельца. Создание issue не означает запуск модели.
- Не менять ядро/submodule, upstream pin, PACKETVER и конфиги другого worker. Свидетель — отдельный NPC-скрипт, не патч ядра.
- Unit-тесты/фикстуры разрешены в своём scope; они не доказательство игры. Миграции только отдельным файлом, deployment выполняет интегратор после review.
- В Git нет паролей, API-ключей, profiles с credentials, БД, сырых логов и бинарников.
- PR содержит diff, команды и фактический вывод проверок, ограничения, изменения контрактов (если согласованы). Self-report worker не означает accepted.
- Не пушить прямо в main, не merge/deploy: интегратор объединяет совместимые PR и проверяет совокупный runtime.
- Текущая очередь — веха A. Веха B и все последующие фичи заблокированы до принятия предыдущей. Никаких LLM, голосов и отношений сейчас.
