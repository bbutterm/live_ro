# Устойчивое управление при медленном свидетеле — 2026-10-10

## Причина и исправление

Gateway выполнял SELECT свидетеля синхронно внутри того же цикла, который обслуживает управляющий сокет и heartbeat тела. Восьмисекундное ожидание SELECT превышает трёхсекундный таймаут клиента; обработка исключения сама по себе не устраняет блокировку цикла.

SELECT перенесены в один ограниченный поток на gateway. Одновременно существует только один пакет чтения; очередь не растёт. Только главный поток записывает SQLite, обновляет проекцию и курсоры. При ошибке пакет не применяется и курсоры не продвигаются; старые факты не заменяются выдуманными свежими. Остановка запрещает следующие SELECT, но не выдаёт ожидание текущего запроса за мгновенную отмену.

## Проверка

- Регрессия запускает настоящий gateway и настоящий Unix-сокет. Серверное чтение заблокировано до управляющего запроса. До исправления recv завершается TimeoutError; после status отвечает в пределах 0.5 секунды. Это локальная имитация медленного SELECT, не фактический сбой игрового сервера.
- make check: red — 228 тестов, одна ошибка указанной регрессии; green — 228 тестов OK за 14.769 секунды. Прежняя проверка исключения SELECT и сохранения курсоров также проходит.
- Все три gateway обновлены по очереди через штатное восстановление супервизора. Экономические действия не прерывались; во втором шаге допустили восстановление gateway при обратимом действии. Мир и все игровые тела сохранили PID. Это обновление gateway, не непрерывность их процессов.
- После обновления: 120 секунд, 24 здоровые выборки каждого, ноль ошибок управляющего чтения. Максимальный RPC: ResidentA 0.016 с, Mira 0.030 с, Borin 0.023 с.
- Независимый сервер: по 24 новых позиции каждого, по девять убийств Mira и Borin; ResidentA остаётся в безопасной городcкой паузе при перевесе. ro status: все трое онлайн.

Доказательства вне Git: /var/lib/ro-world/gateway-responsive-{red,green}.log, gateway-responsive-deploy-proof.json, gateway-responsive-live-proof.json.

## Границы

Короткий здоровый отрезок не объявляется двенадцатичасовой приёмкой или проверкой нового естественного die. Параллельное чтение не чинит нехватку памяти сервера и не доказывает, что любые задержки исчезли. Стартовая загрузка старого журнала и baseline по-прежнему выполняется до готовности сокета.
