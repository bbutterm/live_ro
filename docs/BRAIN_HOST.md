# Хост мозгов: один процесс Python на N жителей (ORG-048) — проект

Статус: **проект, не реализован.** Код ниже не написан; цифры — локальные замеры в песочнице (Python 3.11,
Linux x86_64), на VPS не снимались. Зависит от ORG-047 (`scripts/lab resources`, `brain/live_brain/resources.py`):
после развёртывания замера нужно повторить оценку на реальных жителях за 6 ч.

## 1. Зачем

Сейчас каждый житель — два процесса: тело (OpenKore, perl) и мозг (`python3 -m live_brain --bot botNN`).
Мозг почти всё время ждёт (тик раз в секунду, сокет, редкие вызовы модели), но держит свой интерпретатор,
свои копии модулей и справочников. На VPS с ограниченной RAM это прямой налог на каждого нового жителя.
Цель ORG-048: при 4 жителях суммарный RSS мозгов меньше на ≥ 30 % при тех же тестах.

## 2. Замеры (локально, `brain/`)

| что | RSS |
|---|---|
| голый `python3 -c pass` | ≈ 8 МБ |
| + `asyncio, sqlite3, json, logging` | ≈ 20 МБ |
| + `import live_brain.__main__` (все 26 модулей) | ≈ 25 МБ |
| реальный процесс мозга без тела (`python3 -m live_brain`, BRAIN_LLM=off, 5 с после старта; `scripts/lab resources`) | **≈ 29 МБ** |
| один процесс, 1 разум `Mind` (память, мир, 30 тиков) | ≈ 30 МБ |
| один процесс, 4 разума | ≈ 33 МБ |
| один процесс, 8 разумов | ≈ 36 МБ |

Методика: `Mind` с отдельной `Memory` (SQLite) и миром `goals.json`, состояние тела подано через `on_message`,
затем 30 вызовов `step()` для каждого; RSS — `VmRSS` из `/proc/self/status` после `gc.collect()`. Скрипт —
одноразовый, в репозиторий не входит; повторить на VPS можно тем же способом.

Оценка для 4 жителей:

- сейчас: 4 × ≈ 29 МБ ≈ **116 МБ**;
- хост: ≈ 25 МБ (интерпретатор + модули, один раз) + атлас/цены (`atlas.json` 650 КБ и `prices.json` 510 КБ
  в разобранном виде — несколько МБ, один раз) + ≈ 1 МБ на разум ≈ **33 МБ**;
- с запасом на рабочие данные (кэш страниц SQLite: по умолчанию до 2 МБ на соединение, у жителя их три —
  память, общий бюджет, шина мира; журнал решений; очередь поводов) — до ≈ 7 МБ на жителя: 25 + 4 × 7 ≈
  **55 МБ**.

Экономия **≈ 50–70 %** (цель ≥ 30 % выполняется с запасом). Тела хост не трогает. Размер тела (perl OpenKore с
таблицами и плагинами) здесь не замерен — ожидаемо оно больше мозга, и тогда основной расход RAM за телами, а для
онлайна важнее ORG-044 (сон освобождает процесс тела), чем хост мозгов. Проверить `scripts/lab resources` на VPS.

## 3. Устройство

```
python3 -m live_brain.host --env FILE --lab-root DIR --bots "bot01 bot02 …"
  └─ asyncio loop
       ├─ Resident(bot01): Bridge(run/brain/bot01.sock) + Memory(state/bot01) + Mind + inbox + decisions
       ├─ Resident(bot02): …
       ├─ общие: SharedBudget, WorldBus (одно соединение), атлас, цены, мир goals.json (только чтение)
       └─ сторожок задач: упавший Resident перезапускается внутри хоста, с лимитом и оповещением
```

`Resident` — то, что сейчас делает `main_async` для одного бота: сокет, `Mind`, задача `mind.run`, замер
ресурсов. Протокол с телом не меняется: каждый житель слушает свой `run/brain/<bot>.sock`, плагин brainBridge
ничего не замечает. Пути на диске те же (`state/<bot>/memory.sqlite`, `decisions.jsonl`, `run/brain/<bot>.inbox`,
`.asleep`) — `scripts/lab plan/gift/report/routine show` работают без изменений.

### Разделяемое (одно на хост)

| что | сейчас | в хосте |
|---|---|---|
| интерпретатор, модули | по копии на жителя | одна |
| `atlas.default()` (`atlas.py`, модульный синглтон) | по копии | одна, только чтение |
| `prices._CACHE` (`prices.py`, модульный dict) | по копии | одна, только чтение |
| мир `goals.json` (`load_world`) | по копии | читать на жителя или `deepcopy`: `merged_routine`/`merged_social` делают поверхностные копии, вложенные dict общие |
| общий бюджет моделей `state/shared/budget.sqlite` | соединение на процесс, `BEGIN IMMEDIATE` между процессами | одно соединение; `SharedBudget(path, bot)` привязан к боту — нужен параметр `bot` в `reserve` или по объекту на жителя |
| шина мира `state/shared/world.sqlite` | `WorldBus(path, bot)` на процесс | одно соединение, автор — параметр |
| пул потоков для вызовов моделей (`run_in_executor(None, …)`) | свой на процесс | общий: min(32, CPU + 4) потоков — на 1–2 CPU это 5–6 одновременных вызовов на всех; при BRAIN_LLM=off не используется |
| env-файл, `Settings` | на процесс | один `Settings`; лимиты на бота остаются в памяти жителя |

### Изолированное (на жителя)

`Memory` (своя SQLite), `Mind` и все модули (`Routine`, `Economy`, `Social`, `Needs` …), `Bridge`/сокет,
inbox, `decisions.jsonl`, `persona` (мутирует: `learn_hunt_map` дописывает `hunt_maps`), `random.Random` модулей
(у каждого свой `rng`), отметки
`ctx.last`, очередь поводов, флаг сна.

### Глобальные состояния, мешающие хосту

1. **Логирование.** `logging.getLogger("mind" | "routine" | …)` без имени жителя, `basicConfig` в `main`.
   В одном процессе строки жителей перемешаются. Нужно: `contextvars` с именем жителя + `logging.Filter`,
   добавляющий его в формат; задача каждого `Resident` ставит свою переменную контекста. Журналы по жителю
   (`logs/<bot>/brain.log`) — `FileHandler` с фильтром по контексту.
2. **`atlas._default` / `atlas.reload()`** — синглтон модуля: перезагрузка атласа меняет его всем жителям сразу
   (сейчас — только своему процессу). Желательно, но должно быть явной операцией хоста.
3. **`prices._CACHE`** — общий кэш разобранного JSON; безопасен, пока никто не меняет `Prices.data` на месте
   (сейчас не меняет — закрепить тестом).
4. **Модульные dict-константы** (`economy.MARKET`, `social.DEFAULTS`, `prices.DEFAULTS`, `REASON_TTL` …) —
   копируются через `dict(...)` перед изменением; вложенные значения общие. Проверить, что ни один модуль не
   меняет вложенные структуры конфигурации.
5. **Сигналы** (`loop.add_signal_handler` в `main_async`) — один обработчик на хост, останавливает всех.
6. **Синхронные коммиты SQLite в цикле событий.** `Memory.add_event`/`set` делают `commit()` прямо в
   корутинах. В отдельном процессе пауза на fsync тормозит одного жителя, в хосте — всех. WAL +
   `synchronous=NORMAL` (ORG D7) уже снижают цену; нужен замер задержки тика при N жителях, при росте —
   отдельный поток записи.
7. **Глобальный `random`** — запасной вариант в `maps.MapStats.choose`, если `rng` не передан. Оба текущих
   вызова (`routine.pick_map`, `activity`) передают `rng` жителя; новый вызов без него сделает последовательность
   общей для всех жителей хоста (воспроизводимость реплея по жителю пропадёт).

## 4. План миграции

1. **Подготовка без смены процессов** (можно делать сразу): контекст жителя в логах; `SharedBudget.reserve`
   и `WorldBus.publish` с параметром автора; `MapStats.choose` — `rng` обязательный; тест «два `Mind` в одном
   процессе не делят состояние» (persona, routine.st, reasons, ctx.last).
2. **`live_brain.host`** рядом со старым входом: `Resident` = текущий `main_async` без сигналов и `basicConfig`.
   Старый `python3 -m live_brain --bot` остаётся (хост из одного жителя).
3. **`scripts/lab`**: `LAB_BRAIN_HOST=1` — `start_brain` поднимает один процесс `brain-host` вместо
   `brain-<bot>`; `find_procs brain-<bot>` узнаёт жителя по `--bots` хоста; сторож перезапускает хост целиком,
   если он упал, а отдельного жителя перезапускает сам хост. По умолчанию выключено.
4. **Замер**: `scripts/lab resources` до/после при 4 жителях за 6 ч (RSS, CPU, задержка тика из
   `decisions.jsonl`), реплей ORG-050 через хост с тем же результатом, что через отдельные процессы.
5. Включение на VPS — только с разрешения владельца; откат — `LAB_BRAIN_HOST=` и `scripts/lab down && up`.

## 5. Риски

- **Радиус отказа.** Исключение вне `Mind` или утечка памяти роняет всех жителей сразу. Смягчение: задачи
  жителей под присмотром хоста (перезапуск `Resident` с лимитом, как `sup_restart`), сторож поднимает хост.
- **Голодание цикла.** Один житель с долгой синхронной операцией (SQLite, разбор большого JSON, `prune`) задерживает
  тики всех; правила безопасности (лечение, бегство) реагируют позже. Нужен замер задержки тика и бюджет на
  тик.
- **GIL / один CPU.** Все мозги на одном ядре. По замеру ORG-047 мозг тратит доли процента CPU, так что
  при 4–8 жителях это не ограничение; при включённой модели парсинг ответов идёт в том же потоке.
- **Пул потоков моделей** общий: при включённых LLM и JEV ожидание свободного потока увеличит задержку ответов
  на события. Отдельный `ThreadPoolExecutor` с явным размером.
- **Смешение логов и журналов** — см. п. 3.1; без него разбор инцидентов станет хуже, чем сейчас.
- **Совместимость со сторожем, `report`, `plan`, ORG-044** — пути файлов и сокетов не меняются, но
  `running_pid brain-<bot>` и мягкая смена (`ask_sleep` проверяет, что мозг запущен) должны понимать хост.
- **Экономия меньше ожидаемой**, если тела, а не мозги, — основной расход (вероятно). Решение о хосте —
  после 6-часового замера `scripts/lab resources` на VPS.
