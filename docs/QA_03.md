## Durable inbox
Reader `--store PATH --source-id GENERATION --duration SECONDS` persists whole source rows and cursor in one SQLite transaction. `--after` must be zero in store mode; actual cursor comes from SQLite. Storage is a durable inbox, NOT an exactly-once downstream action engine. stdout is diagnostic; a crash after commit and before printing does not replay stdout.

Real SELECT-only reader run saved 4430 unique rows, cursor4430. Two separate CLI processes emitted disjoint sets (4428 and2 rows). Inbox contains actual kill3328/loadmap3402/die3431. SQLite rollback, replay deduplication and same-id/different-payload rejection have unit tests (synthetic unit fixtures, not gameplay evidence).

Bounded query recovery: at most3 fresh MariaDB client attempts, .25/.5s backoff,8s query timeout each. Real unavailable local defaults file then restored protected configuration recovered on attempt2 and read200 real rows including die3431. Exhaustion leaves durable cursor unchanged. Shared MariaDB/server services were NOT restarted for this test. Retries also have a mocked unit test; it is not presented as a database-outage test.
