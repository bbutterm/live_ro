# Исправление обслуживания и обмена — VPS QA

## Обмен: причина и исправление

`economy::distanceTo` использовал `pos_to`: конечную точку текущего движения. Сделка предлагалась до фактического приближения, сервер возвращал «слишком далеко».

Простая замена на `pos` оказалась недостаточной: OpenKore хранит там начало последнего отрезка. Это доказано живой диагностикой: `pos=(162,66)`, `pos_to=(161,56)`, тогда как персонаж уже стоял у точки отдыха. Такой вариант застревал в `approach`; он заменён штатным `Utils::calcPosition` для обеих сторон. Ограничение rAthena в две клетки, проверка адресатов и подтверждение результата сервером не изменены.

Окончательное исправление: `adb7fa8` (предшествующая промежуточная правка `eaa1401` не является окончательным решением). Плагин обновлён в runtime и перезагружен у обоих клиентов без перезапуска rAthena.

Это реальная сделка, а не только успешный приём команды.

## Текущий режим и ограничения

Для изолированного теста обмена временно выключен только модуль `activity`, прочие существовавшие rollout-ограничения сохранены. Попытка автоматического восстановления режима заблокирована инструментом без исполнения команд. После вопроса оператор выбрал **«Пока оставить обоих в городе для дальнейшей проверки»**. Возврат на охоту по команде QA не выполнялся; восстановление выбора занятий остаётся отдельным завершающим действием.

Полный предыдущий Python-прогон: 1140 тестов, 82 failures, 21 errors. Он не является зелёным. Исправление изоляции тестовых fixtures и новый полный прогон ведутся отдельно; этот отчёт не объявляет весь пакет принятым. Новых персонажей не создавали, игровую БД и сервер не меняли.
