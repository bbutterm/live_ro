# Новый мир на чистом VPS — одной командой

Чистый Ubuntu 24.04, root, не меньше 4 ГБ RAM (swap скрипт добавит сам), от 20 ГБ диска, исходящий HTTPS к github.com.

```
git clone https://github.com/bbutterm/live_ro.git /root/ragnarok/repos/live_ro
cd /root/ragnarok/repos/live_ro
python3 tools/deploy_world.py --only system   # пакеты и часовой пояс UTC
make check                                    # должен быть зелёным
python3 tools/deploy_world.py                 # всё остальное, 20–40 минут
```

- Если в `.env` нет ключа, скрипт создаст файл из `.env.example`, а жители будут жить на привычках. Владелец вписывает `RO_WORLD_LLM_API_KEY=...` в `/root/ragnarok/repos/live_ro/.env`. Перезапуск не нужен: мозг подхватит ключ в течение минуты, проверка — `tools/ro doctor`.
- Скрипт проверен целиком на чистом Ubuntu 24.04. В режиме без systemd (`--dev`) мир поднялся за 9 минут, а повторный запуск ничего не сломал.

## Мир уже развёрнут — настроить жителей
Если rAthena и БД уже подняты, например по прежней ручной инструкции:
```
cd /root/ragnarok/repos/live_ro && git pull origin main
python3 tools/deploy_world.py --inspect     # только чтение: что уже есть, без секретов
python3 tools/deploy_world.py               # готовое пропускает, доделывает жителей
```
- **Что скрипт доделывает.** Профили OpenKore, персонажи через протокол клиента, регистрацию в свидетеле, узкого пользователя для follow, службы `ro-world` и `ro-chat`.
- **Перезапуски.** Если мир уже работал на старом коде, `ro-world` и `ro-chat` перезапускаются на новый (жители переподключаются сами). Если скрипт поменял настройки rAthena или часовой пояс MariaDB на UTC, серверы rAthena тоже перезапускаются один раз.
- **Если раскладка другая** — `--inspect` покажет другие пути, другие БД или чужой `map-server`. Тогда ничего не запускать, а вывод `--inspect` прислать владельцу.

## Что делает скрипт
Каждая фаза сначала проверяет, сделана ли она. Готовое не трогается, поэтому после любой ошибки достаточно запустить скрипт снова: `--from ФАЗА` продолжает с нужного места. Секреты на экран не выводятся.

| Фаза | Что делает |
|---|---|
| `system` | часовой пояс UTC (время свидетеля без перехода на зимнее время), пакеты, swap, пользователь `ro-residents`, каталоги |
| `sources` | rAthena `e985006` и OpenKore `51de1dd` — настоящие каталоги в `/root/ragnarok/repos` |
| `rathena_build` | патчи `server/patches`, сборка renewal с `PACKETVER 20180620` (10–30 минут) |
| `database` | MariaDB в UTC с `myisam_recover_options`, схемы rAthena (`tools/provision_a1.py`), схема свидетеля, читатель свидетеля только с SELECT (`reader.cnf`), узкий пользователь регистрации гостя для follow (`registry.cnf`: только `residents.registry`) |
| `rathena_config` | без PIN, старт новичков в Пронтере, журналы чата и денег, NPC свидетеля, права для `ro-residents` |
| `rathena_services` | юниты login/char/map с автоперезапуском, только 127.0.0.1, logrotate |
| `openkore` | XSTools, проверка плагина `residentBody`, поля карт из кэша rAthena |
| `profiles` | аккаунты: пароль сохраняется до создания аккаунта, повторный запуск доводит недоделанное; профили OpenKore |
| `characters` | Tester, ResidentA, Mira, Borin — через обычный протокол клиента, по одному, со сверкой `char_id` 150000–150003; регистрация в свидетеле |
| `world` | venv мозга, `.env`, службы `ro-world` и `ro-chat`; чат перезапускается без лимита и следует за миром |
| `check` | ждёт трёх жителей онлайн, печатает `ro status` и `ro doctor world` |

## Если скрипт остановился
Он пишет `СТОП на фазе …`, причину и команду продолжения. Типичные причины:
- **OpenKore просит пароль или PIN** — профиль сломан. Сообщите владельцу.
- **`char_id` не совпал** — БД не пустая. `DELETE`/`UPDATE` персонажей запрещены: новые id впишите в `config/world.yaml` и `residents.yaml` коммитом.
- **Не открылся порт** — смотрите `/root/ragnarok/logs/*-server.log`.
- **Не все трое онлайн за 5 минут** — смотрите `/var/lib/ro-world/*-body.log` и `world.log`.

Журнал скрипта лежит в `/root/ragnarok/logs/deploy.log`.

## Настройки этого сервера
Только `/var/lib/ro-world/world.local.json`, не git. Разрешено задавать:
- по жителям: `enabled`, `persona`, `support_target`, `duo_partner`, `party_search_consent`;
- в `llm`: `enabled`, лимиты, `menu`;
- `daily_llm_usd`.

Ошибка в файле видна первой строкой `ro status`, а мир в это время работает на последней верной копии. Пример — выключить LLM для проверки чата:
```
{"llm": {"enabled": false}}
```

## Приёмка (готово = свидетель + ro status)
```
tools/ro status                 # 3 жителя «онлайн … решил сам (LLM)», строка мозга без «пауза до»
tools/ro doctor world           # службы, свидетель, чат, версия кода, диск, бэкап — ИТОГ: PASS
tools/ro accept --window 6h     # критерии ТЗ §1 за 6 часов — PASS/FAIL по каждому
```
Суточная приёмка пассивная: мир просто работает, через сутки запускается `tools/ro accept --window 24h`. JSON итога лежит в `/var/lib/ro-world/accept-24h.json`.

## Вход владельца
Клиент RagexeRE 2018-06-20 через SSH-туннель на порты 6900, 6121 и 5121. Серверы слушают только 127.0.0.1. Аккаунт владельца создаётся по отдельной просьбе.

## Известные риски
- **Неверные входы.** 7 неверных входов за 5 минут с 127.0.0.1 банят localhost для всех тел на 5 минут.
- **Сокет `tools/residents`.** По умолчанию он стучится в старый сокет, поэтому передавайте `--socket /var/lib/ro-world/<rid>/actions.sock.control`.
- **Новички слабы.** На prt_fild08 они иногда погибают и сами возрождаются. Распределение очков и смена профессии — этап 4 плана.
