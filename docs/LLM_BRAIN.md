# Мозг жителей на LLM: как включить

Житель живёт сам. Каждый ход он осматривается, вспоминает свой дневник и план и спрашивает свою LLM: «что мне делать дальше?» LLM выбирает одно действие из меню. Тело (OpenKore + `residentBody`) его выполняет, а свидетель сервера подтверждает результат. Если LLM недоступна, житель живёт на привычках и сам возвращается к LLM, когда она снова доступна.

## Включить — 3 шага

1. Вставить токен в `/root/ragnarok/repos/live_ro/.env` (шаблон — `.env.example`):
   ```
   RO_WORLD_LLM_API_KEY=sk-or-...
   ```
   Больше ничего не нужно. По умолчанию используется OpenRouter и `deepseek/deepseek-v3.2`. Подойдёт любой OpenAI-совместимый провайдер: для этого задайте `RO_WORLD_LLM_BASE_URL` и `RO_WORLD_LLM_MODEL`.
   - Файл можно сохранить в UTF-8, UTF-16 (Блокнот) или cp1251; кавычки и комментарий `# ...` после ключа не мешают.
   - Ключи с именем провайдера используются только у своего провайдера: `OPENROUTER_API_KEY` — только с OpenRouter, `OPENAI_API_KEY` — только с `api.openai.com`, `DEEPSEEK_API_KEY` — только с `api.deepseek.com`. Ключ OpenAI, случайно оставшийся в окружении, не уйдёт в OpenRouter.
2. Проверить токен одним дешёвым вызовом:
   ```
   tools/ro doctor
   ```
   Ожидаемый ответ — `OK: ...`. Если что-то не так, команда по-русски объяснит, что именно: нет токена, ключ не принят, нет денег, лимит, нет сети. Она же пишет, откуда взят ключ, и предупреждает, если ключ есть только в окружении оболочки: службы systemd его не видят, им нужен `.env`.
3. После обновления кода перезапустить мир. Тела должны загрузить новый плагин, мозги — новый код:
   ```
   systemctl restart ro-world.service ro-chat.service
   tools/ro status
   ```
   Позже для смены токена перезапуск не нужен: `.env` перечитывается при каждом вызове.

## Лимиты: ждёт и продолжает сам

| Что случилось | Что делает мир | Когда LLM снова пробует |
|---|---|---|
| 429 — лимит запросов, разово и коротко | житель стоит и «думает» | по `Retry-After` (+разброс) |
| 429 повторяется | на привычках | 20 с → 40 с → … ≤15 мин (+разброс), не меньше `Retry-After` |
| 402 — нет денег на счёте | на привычках | через 10 мин (пополнили — подхватит сам) |
| 401/403 — ключ не принят | на привычках | через 10 мин; `tools/ro doctor` проверяет сразу |
| нет токена в `.env` | на привычках | каждую минуту |
| провайдер лёг, нет сети / мозг не дождался ответа за 25 с | первые две короткие паузы подряд стоит и «думает», дальше — на привычках | 10 с → 20 с → … ≤5 мин (+разброс) |
| чат не успел ответить к сроку (≈6.5 с после реплики) | этот ответ — быстрой фразой | через 5 с; общая пауза не ставится |
| дневной лимит `daily_llm_usd` | на привычках | проверка раз в 5 мин (подняли лимит в `.env` — подхватит), иначе после полуночи UTC |

Пауза общая для всех жителей и для чата: она хранится в `/var/lib/ro-world/llm-gate.json`. Её снимает только успешный ответ на запрос, начатый после паузы.
- Параллельный таймаут не сокращает паузу, назначенную провайдером.
- Если три жителя одновременно получили один и тот же 429, это одна пауза, а не три шага эскалации.
- Разброс: шлюз добавляет до 20%, каждый житель — ещё до 20% (не больше 30 с), всего до ~45%. Поэтому жители не стучатся к провайдеру одним залпом.
- Житель стоит и «думает», только если пауза короткая (до `short_pause_seconds`, по умолчанию 60 с), не из-за денег, токена или лимита и это первая или вторая такая пауза подряд. С третьей подряд он живёт на привычках до первого успешного ответа.

## Деньги

- Учитывается только фактическая стоимость каждого ответа. У OpenRouter это `usage.cost`, у других провайдеров — токены × `RO_WORLD_LLM_PRICE_IN/OUT`. Резервов «на всякий случай» нет, поэтому лимит не может «кончиться» при реальных тратах 8% (ошибка E04 и ночь «без API»).
- Журнал по UTC-дням — `/var/lib/ro-world/llm-spend.json`.
- Если день тратится быстрее, чем идёт, паузы между решениями сами растут, чтобы денег хватило до вечера.
- Ориентир для DeepSeek V3.2: ~$0.0005 за решение. Три жителя, 15–20 решений в час — примерно $0.5–1 в сутки.
- Чат: каждый житель отвечает одному собеседнику через LLM не чаще 3 раз за 2 минуты, остальное — быстрыми фразами. Если день тратится слишком быстро, чат тоже отвечает быстрыми фразами, чтобы деньги остались на жизнь. Если разговор прервал решение мозга, это решение сохраняется и перепроверяется после разговора без нового платного вызова (если ему не больше 2 минут).
- Брошенный по таймауту запрос записывается в журнал по оценке входных токенов: провайдер может его списать.
- Траты V1 (canary под lease) тоже попадают в `llm-spend.json`.

## Что видит LLM и что может выбрать

- Видит: где житель, здоровье, вес, зени, зелья, сколько добычи на продажу, кто рядом (житель или игрок, на каком расстоянии), факты сервера (убийства, смерти, карты, уровни), что ему сказали и что он ответил, итоги последних дел. Плюс свой план и дневник (`/var/lib/ro-world/<житель>/plan.json`, `diary.json`).
- Видит пометку `can_now` — что можно делать сейчас и почему нельзя остальное. Например: «нельзя: перевес, сначала продай добычу».
- Действия:
  - `hunt` — 5–15 мин, поринги на `prt_fild08`;
  - `town_service` — продать добычу и купить зелья;
  - `rest`;
  - `walk_to` — 14 мест Пронтеры и поля, все клетки проверены по кэшу карт rAthena;
  - `say`, `whisper`, `follow`, `meet`, `idle`.
- Шептать себе нельзя: собственное имя не попадает в `can_now.whisper`, а такой ответ модель получает на исправление.
- Ответ модели разбирается мягко: синонимы действий, числа текстом, лишние поля, аргументы плоско или во вложенном `args`. Если ответ не подошёл, модель получает одну попытку исправиться и точную причину отказа.
- Честность сохранена:
  - обещание движения без движения не произносится («иду», «идём», «пойдёмте», «подойду», «приду», «бегу», «уже в пути», «скоро буду у…»);
  - чужие слова — не команды;
  - шептать можно только тем, кто рядом, жителям или тем, кто недавно говорил с жителем;
  - GM, SQL и консоли нет;
  - речь уходит прямо в чат-пакет, а не в консоль OpenKore, поэтому `;;` в тексте не может стать командой.

## Где смотреть

- `tools/ro status` — где каждый житель, что делает, решил ли сам (LLM) или по привычке, о чём думает. Последняя строка — состояние мозга: модель, траты за день, пауза и её причина.
- `/var/lib/ro-world/decisions.jsonl` — по одной строке на событие:

  | Запись | Что в ней |
  |---|---|
  | `MODEL_DECISION` | мысль, действие, план |
  | `MODEL_CALL` | стоимость, режим, время |
  | `MODEL_UNAVAILABLE` | причина и время возобновления |
  | `MODEL_REPAIR` / `MODEL_INVALID` | сырой ответ модели |
  | `GOAL_OUTCOME` | итог, подтверждённый сервером |

## Что исправлено по аудиту

- **E04 и ночь «без API».** Фантомные резервы и двойной счёт заменены учётом по факту.
- **Хрупкий путь решений.** Был JSON-mode и жёсткий валидатор. Теперь строгая `json_schema` (если провайдер её не умеет — `json_object`, затем текст), мягкий разбор и одна попытка исправиться.
- **Чат и решения больше не мешают друг другу.** Раньше во встроенном режиме чата ошибка чата замораживала выбор занятий.
- **Договорённость из разговора выполняется один раз.** Например, «встретимся у фонтана» исполняется под своим id задачи. Раньше повтор id ответа давал `MEETING_ID_CONFLICT` по кругу. Даже если исполнение упало, договорённость снимается, а мозг после неё думает заново.
- **Встреча с занятым соседом.** Если сосед сам охотится, ждёт или следует дольше окна встречи и его мозг действительно занят (держит `manual.lock`), встреча сразу завершается `TARGET_BUSY` без голосования. Брошенный файл задачи упавшего мозга встречу не блокирует.
- **Модель знает, что ответ не дошёл.** В истории разговора «я ответил» ставится только у реплик, подтверждённых телом. Для остальных — «не смог ответить».
- **Токен подхватывается без перезапуска.** Раньше сбой инициализации отключал LLM до рестарта процесса.
- **E05: перевес.** Тело продаёт добычу по типу предмета (типы rAthena): лечебный лут вроде яблок и трав, etc, оружие, броня. Не продаётся надетое, зелья 501–506, крылья, драгоценные камни, расходники, карты, стрелы и яйца питомцев. Gateway подтверждает продажу по picklog сервера. Если торговец отказался купить часть добычи, это не мешает подтверждению и покупке зелий.
- **Безопасность речи.** Раньше текст речи шёл через `Commands::run`, где `;;` разделяет консольные команды OpenKore. Теперь речь отправляется через `Misc::sendMessage`.
- **E01 в V1.** Кадр монстра из плагина приводится к контракту `{id: класс, x, y}`.
- **E06 в V1.** Собственный `interrupted` больше не ставит пятиминутный cooldown.
- **Логирование.** Ошибки модели теперь пишутся с причиной и сырым ответом, а не только с именем исключения.

## Чем проверено и что НЕ проверено

- `make check` и новые тесты:
  - `test_world_llm` — клиент против локального HTTP: 429, 402, 401, 5xx, дневной лимит, токен без рестарта, `ro doctor`;
  - `test_world_mind_brain` — разбор ответов, `can_now`, повторная попытка, пауза, дневник, темп бюджета;
  - `test_world_brain_e2e` — настоящий цикл мозга с настоящим gateway, телом по протоколу плагина, свидетелем сервера и LLM: решения → действия → подтверждения, 429 посередине → привычки → LLM снова;
  - перловые тесты плагина на заглушках OpenKore: продажа по типу, настоящий кадр монстра через контракт V1.
- **В живой игре на VPS это ещё не запускалось.** У разработчика нет доступа к стенду и токену. Первый запуск — шаги 1–3 выше, затем `tools/ro status` и `decisions.jsonl`. Если в `decisions.jsonl` есть `MODEL_DECISION`, а в `GOAL_OUTCOME` — `done`, значит модель управляет жителем.
- Правка плагина (продажа по типу) проверена только на заглушках. Полный OpenKore без собранного XSTools вне VPS не грузится. На VPS в тесте `test_perl_compile_against_actual_openkore` плагин компилируется с настоящим OpenKore.
- Если в `/var/lib/ro-world/<житель>/` остался файл `BEHAVIOR_V1` после canary, плагин работает в режиме V1 с его ограничениями. Для нового мозга этого файла быть не должно.
