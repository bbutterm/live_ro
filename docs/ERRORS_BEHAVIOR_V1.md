# Resident Behavior V1 — ошибки и незакрытые ограничения

Срез: 2026-10-10, 19:39 UTC. Реестр известных проблем этого внедрения; не обещание, что неизвестных дефектов нет.
Источник runtime: `/var/lib/ro-world/resident_a/behavior-live.jsonl`; сырые логи и токены в Git не копируются.

## Аудит 2026-10-10: причины найдены (ветка claude/resident-llm-brain)

- E01: плагин кладёт в near_monsters {id: GID, nameID, x, y}, контракт требует ровно {id,x,y}; к тому же Python сравнивает id с '1002' (класс), а приходит GID. Исправлено нормализацией в bridge.monsters_v1; регрессия на настоящем кадре плагина.
- E02: промпт decision противоречит валидатору (optional say vs запрет say, нет lines), свой выбор модели разрешён в 10% случаев, args сравниваются побайтно (10.0≠10), нет strict schema. Причина отказа не логировалась. В V1 не исправлялось: основной мозг теперь resident_world (docs/LLM_BRAIN.md).
- E04: резерв на вызов ≈(байты+4096)·цена·2, не гасился и складывался с фактическим usage — лимит $2 «кончался» при ~$0.16. Новый мозг считает только фактическую стоимость ответа (llm-spend.json).
- E05: тело подбирает всё, а продаёт 3–7 id. Теперь продаёт добычу по типу предмета (не надетое, не зелья/карты); gateway подтверждает по picklog.
- E06: Adapter ставил 5-минутный cooldown на собственный 'interrupted'. Исправлено.

## Открыто — блокирует игровую приёмку

### E01. Runner падает с ContractError: invalid_keys
- Факт: 19:35:51 UTC во время принятого walk_to(poring_edge).
- После ошибки runner начал drain; сначала unresolved_native, затем failed/interrupted и released в 19:37:08 UTC.
- Точная причина/место несовместимого envelope не локализованы; нельзя выдавать предположение за исправление.
- Нужно воспроизведение по обезличенным envelope, regression и повторная серверная проверка.

### E02. Decision-ответ DeepSeek отклонён
- Единственная decision-попытка текущего canary: request_sent=true, cost=0.00012026 USD, fallback_reason=invalid_response.
- Движение accepted, но source=fallback. Это не доказательство автономного решения модели.
- Chat strict schema отдельно заработала; decision по-прежнему JSON-mode. Причину конкретного decision rejection ещё нужно извлечь, без ослабления action/args guards.

### E03. Чат остаётся выбором готовых фраз
- Даже успешный provider chat выбирает из одобренных строк, а не создаёт свободный ответ по смыслу.
- Это одна из причин однообразия. Более содержательный разговор и безопасное grounding пока не реализованы/не приняты.
- Во время canary ноль chat_outcome: реальный ответ игроку и исполнение просьбы не подтверждены.

### E04. Зависшие старые денежные резервы
- На проверке допуска: reserved=2.160048268 USD, 528 исторических записей; штатный cap=2 USD.
- Резервы НЕ равны подтверждённой стоимости. Без receipt их нельзя объявить потраченными или просто стереть.
- Settlement новых подтверждённых запросов реализован; историческая сверка не завершена.
- Владелец разрешил временно не блокировать проверку этим лимитом: cap=3 только в контролируемом lease одного жителя, <=20 минут. После released/expiry снова 2; неизвестные резервы сохранены.

### E05. Перевес без продаваемой добычи
- Свежий ro status: все трое в безопасной паузе в prontera.
- Whitelist не расширялся, предметы/деньги через SQL/GM не менялись.
- Без разрешённого игрового способа разгрузки полноценное разнообразие поведения ограничено.

### E06. Перерыв и отклонённые idle
- До движения наблюдались controlled/break, llm_allowed=false и rejected idle с error_code=interrupted.
- Перерыв не был вечным: позже запрошено движение. Однако повторяющиеся rejected idle требуют отдельной локализации.
- Отсутствие LLM-вызовов в таком срезе нельзя выдавать за работающий выбор ИИ.

### E07. Неполная приёмка/reconciliation
- Ранний drain не заменяет успешный canary; rollout на остальных жителей не выполнен.
- B2 final completeness и §7 SPEC остаются открыты.
- Нужны отдельные игровые доказательства handoff/crash windows, restart dedup, unknown/terminal-failed movement без обещания, lease crossover и malformed inbox без остановки runner.
- Автономные встречи через новый Controller не включены: нет доказанной отдельной резервации/согласия.

## Исправлено в коде и проверено регрессиями, но не полностью принято в игре

### F01. Речь могла остановить общий motor
Speech-specific stop отменяет только свои native ID; без global safe_stop и ожидания IDLE_SAFE.
Регрессии say/whisper при движении и compound town_service: timeout, interrupt, stale, dead.

### F02. Чат затрагивал planning cadence/RNG
Убран вызов Controller.step из обработчика речи; арбитраж отдельный, выбор привычек при chat consumption не запускается.
Regression сохранения next_plan_at/decision_index/plan_tick_index/rng_index проходит.

### F03. Chat JSON содержал лишний say
Реально наблюдалось: модель вернула одновременно args.text и say; validator правильно отклонил ответ.
Неоднозначность prompt убрана; provider chat переведён в strict JSON schema и require_parameters.
После изменения реальный backend ответ валиден; доставка игроку этим вызовом не проверялась.

### F04. Unit test зависел от реального lease
При активном canary test_brain_execs_isolated_interpreter_without_restarting_bodies попал в live runner и получил KeyError(name).
Тест изолирован временным STATE; runtime не исправлялся путём ослабления ownership guard.

### F05. Ошибки интеграции, закрытые red → green
Неверный вызов fallback_reply; несовпадение read_lease/lease_active API; отсутствие fsync при передаче события;
неправильные fixture clock/position; отсутствие model selection через общий Client.
Исправлены; последний общий gate 433 теста OK. Старые red-логи не являются актуальным состоянием этих регрессий.

## Известные смежные исторические ограничения

- Полнота live retry/prelude, встречных meet/decline и новых rest-сценариев не выводится из tests; подробности в DECISIONS.md.
- Подключённые исправления witness SELECT/таймаутов требуют отдельной проверки загрузки и свежих серверных доказательств.
- Безопасная пауза/fallback — штатный защитный исход, но не замена требуемому живому результату.
