# Внедрение RESIDENT_BEHAVIOR_V1

## Адресное включение: canary, не полная приёмка

`/usr/bin/python3 -m packages.resident_behavior.cutover resident_a` проверяет
точные дочерние процессы supervisor и отсутствие активных native-действий.
Только idle brain временно замораживается; его manual flock исключает чатовый
мотор до загрузки fencing. Штатным восстановлением заменяются только gateway,
OpenKore и затем brain этого жителя. OpenKore кратко переподключается;
`ro-world.service`, `ro-chat.service` и другие жители не перезапускаются.
Контроль включается только после свежего `telemetry.behavior_v1=true` и
`ownership.phase=draining` от действительно загруженного gateway.

Lease сохраняет первоначальный deadline ≤20 минут при любом respawn,
его нельзя продлевать. На deadline runner прекращает dispatch, ждёт торговлю,
сверяет native и outbox. Только после доказанного пустого мотора возвращает
legacy; неизвестный исход сохраняет ownership blocked.

`/usr/bin/python3 -m packages.resident_behavior.cutover resident_a --observe 900`
сохраняет живые наблюдения server-position/actions и проверяет PID мира и
остальных детей. Это наблюдение исполнения, не shadow. Runner fallback-only,
без платной модели. Legacy речь отделена от мотора; движение чата fenced,
неподдержанный intent записывается rejected. Social intent inbox ещё открыт.
Исходники/тесты не доказывают deployment: фактическое включение фиксируется
отдельно в STATUS и `/var/lib/ro-world/<actor>/behavior-cutover.json`.

Источник: `docs/RESIDENT_BEHAVIOR_V1.md`, точная копия документа владельца; `config/behavior.yaml` извлечён без изменения формул. Новое поручение заменяет цель завершения прежней AUTONOMY_V1, но не отменяет защиту мира/аккаунтов/секретов/финансов. Новые игровые показатели считаются только по фактическим snapshots, исходные цифры документа — допущения.

## Этапы и трассировка

1. **B1 / §§2–3:** строгий YAML, безопасный AST, veto, utility/decomposition, top3, softmax и сохраняемый RNG Python3.12. Проверка через `make check`, независимый spec-review и quality-review; неизвестное не разрешает действие.
2. **B2 / §2 контракты:** snapshot/events, reducer, одноразовые derived events, drives/mood/цели/отношения/сон; атомарный SQLite store/outbox, idempotency/reconciliation, воспроизводимый replay без тела/сети. Эхо отдельно от намерений.
3. **B3 / §2 мотор + §§5–6:** opt-in OpenKore bridge, один моторный слот, 2-секундное safety, continuation/min_minutes, согласование meet, сон дома/break; шаблонная речь/задержки/канал/лимиты, decision/outcome/speech журналы. Встраивание в постоянный supervisor, сохранение мира и независимости остальных тел; rollback через opt-in, не выключение мира.
4. **B4 / §4:** закреплённый `deepseek-v3.2`, JSON mode и schema кандидатов, prompt≤1536 UTF-8 байт, таймаут8с без повторов; общий $2/UTC-день без сброса старых резервов, раздельные decision/chat квоты. Отсутствующий endpoint не заменять другим провайдером/версией.
5. **B5 / §7:** сначала 72 часа виртуального replay с метками происхождения (не выдавать synthetic за server), затем отдельно 24 часа реального fallback и 24 часа реального LLM. Продолжительность и полнота каждой метрики фиксируются явно; первые короткие игровые гейты — 15–20 минут, не полная приёмка.

## Точки интеграции и решения

- Новый пакет `packages/resident_behavior`, старый `resident_world` остаётся rollback.
- Логические `resident_a/mira/borin` сопоставляются существующим телам `resident_a/resident_b/resident_c` по конфигурации. Имена/классы/уровни/кошельки персонажей не переписываются; «Рат» — персона, не GM-переименование.
- `/usr/bin/python3` — Python3.12.3 с PyYAML; существующий brain-venv3.11 не удовлетворяет указанному RNG runtime. Новое поведение использует штатный Python3.12 без тяжёлой переустановки.
- Старый OpenKore плагин использует зелья ниже55% и учит Basic при rest: это несовместимо с новым v1. Исправление только opt-in; v2-команды не добавляются. Без свежего списка монстров охоту не разрешать.
- Снабжение: только501 и явный избыток909/713/938 сверх целей; частичная продажа требует обновления серверного доказательства, старое «продать всё» не переиспользовать.
- Новый local endpoint18032 сейчас недоступен. Порт не открывался, ключи/провайдер не менялись; безопасный fallback строится независимо. Это блокирует реальную LLM-приёмку, не разработку reducer/utility/adapter.
- Старый общий financial ledger остаётся свидетелем расходов/резервов. Новый quota store не считается новым бюджетным днём и не даёт дополнительного $2.

## Промежуточная сборка B2/B3

- `Controller.step` соединяет snapshot → reducer → derived flags → utility → coordinator → durable outbox → adapter. По умолчанию только чтение; dispatch требует отдельного подтверждения загруженного native v1. Это ещё не supervisor и не полная §7-приёмка.
- Snapshot моторного моста показывает сохранённый корневой мотор, а не последнюю параллельную речь; continuation после пересоздания координатора сохраняет исходный action_id.
- Неопределённый claimed outbox не отправляется повторно. Подтверждённый активный мотор не блокирует safety/mental ticks; новую команду нельзя отправить до подтверждения остановки старой.
- Read-only observer теперь считает derived flags и доступный peer-контекст и сохраняет before/after. Его двухсекундные оценки не являются живыми решениями, платными вызовами или приёмкой поведения.
- Игровой rollout остаётся закрытым до общего `make check`, независимых reviews и свидетельского гейта. Сохранённый код/тестовый transport не подтверждают загруженный plugin.

## Честная граница готовности

Код + unit green ≠ работа в игре; сохранённый plugin ≠ загруженный plugin. Включение только после отдельного review и проверки свидетеля/`ro status`; все runtime-файлы/журналы вне Git. Длительные acceptance-гейты нельзя объявлять закрытыми по короткому прогону или ускоренному replay.
