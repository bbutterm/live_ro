# QA 02: null-session crash и обычный житель

## Crash: RED → GREEN
Во время создания ResidentA после char-selection timeout gdb поймал SIGSEGV: chclif_parse_charselect, char_clif.cpp:1090, через char_packet_db.handle(fd,*sd), char_clif.cpp:1707. Затем отдельный wire-repro без credentials (0x0066, slot0, свежий socket) упал с конкретным assertion: сервер погиб/перезапустился.

Причина: default packet dispatch разыменовывал nullptr char_session_data до handshake. Исправление интегратора — 6 строк null-session rejection перед dispatch. Патч ядра теперь **есть**: server/patches/char-null-session.patch; исходный upstream SHA неизменен. Свидетель всё ещё отдельный NPC, ядро не используется для генерации событий. Пересобран только char, make-j1 exit0.

После изменения тот же checks/char_select_unauth.py PASS: peer connection rejected, server MainPID сохранился. git apply --reverse --check подтвердил соответствие deployed source сохранённому patch. Это не полный security audit и не доказательство отсутствия других crash paths.
